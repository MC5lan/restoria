# Restoria

スキャンしたアーカイブページを、きれいな A4 永久保存文書に — Windows 7 のような古いマシンでも動きます。

向きの検出、傾き補正、ノイズ除去、汚れ除去、階調とトーン調整、そして A4 出力。スキャナオペレータが半日かけていた作業（回転、トリミング、点状の汚れ除去、傾き補正、版面調整）をワンクリックで完了させます。

**単一ファイル。ダブルクリックで起動。データは端末から出ません。**

- **動作環境：** Windows 7 SP1 〜 Windows 11（.NET Framework 4.8、AnyCPU）
- **画面：** GDI+ による完全自前の描画とダブルバッファリングで低性能機でも軽快。ライト／ダークテーマ対応
- **コード：** C# 約 26,000 行、第三者 NuGet パッケージ依存ゼロ。Windows 同梱のコンパイラのみでビルド

## 機能

### ワンクリックパイプライン

向き検出 → ミラー検出 → ノイズ除去 → 傾き補正 → 階調／自動トーン → A4 出力。

- **標準** — 速度と身だしなみのバランス。向きの判定は綴じ穴という物理的証拠のみを信頼します。
- **徹底** — 確実に除去できる塵点だけを削除し、文字を削りかけている場合は自動的に元に戻します。**黒点が残るくらいなら、手書きの線の 1 画も失わないことを優先します。** 綴じ穴のないページでは OCR による向き判定にフォールバックします。薄い手書き文字など、内容が重要な文書向きです。

アーカイブ処理は**新しいファイルを作成するのみ**で、元画像は 1 バイトも変更しません。中断しても再実行すれば完了済みページはスキップされます。バッチごとに、ページごとのサイズ変化・回転角度と根拠・カウント・所要時間を含むレポートを出力します。

### 単一ページの編集

| タブ | 機能 |
|---|---|
| 除去 | ブラシまたは矩形選択で損傷箇所を除去。5 種の補間モード：標準／強化／ブレンド／紙面再構築／AI |
| トリミング | 手動トリミング、または A4 ボードへのスナップ |
| 向き | 手動回転、ワンクリック傾き補正（射影法による検出、±20°） |
| 調整 | 輝度、コントラスト、彩度、色温度、トーンレベル、ガンマ、アンシャープマスク（すべての数値をクリックで直接入力） |
| 印章 | 色褪せた赤い印章の色を補修 |
| 一括 | 固定パラメータでフォルダ全体に適用 |
| スキャン | WIA スキャナに直接接続。出力形式を選択可能（JPG／PNG／TIF） |
| ファイル | 一括リネーム、フォルダ管理 |
| テキスト | ページへの注釈追加 |

### オプショナル AI 補完（MI-GAN）

- ONNX Runtime 1.14.1 が駆動する MI-GAN モデル。破損領域をまたいで罫線のような長い直線構造を延長します
- **子プロセスで読み込み、メインプロセスでは一切読み込みません。** ランタイムが読み込めなければ AI 機能のみが無効になり、他の機能への影響はありません
- Win7 対応：インポートテーブル書換によるシム（詳細は `src/Ai/AiFill.cs` のコメントを参照）

`ai/` ペイロードは 30 ファイル、約 59 MB で、AI 補完と印章 OCR にのみ使用されます。

### エンジニアリング

- **134 件のヘッドレス自己テスト**（`--selftest`）：アルゴリズム閾値、アンドウの予算、リカバリ場所、ショートカットの競合
- **レイアウトベースライン回帰**（`--layout`）：UI リファクタリングで何も変わっていないことの客観的証拠
- **4 つのゲート**（`tools/gate.py`）：自己テスト、レイアウトベースライン、AI 生成物、性能スモークテスト
- **継続的インテグレーション**：GitHub Actions が push のたびにビルドとゲートを実行
- アーカイブ出力の並列回帰あり（徹底モードの parallel=1/2/4 はバイト単位で一致）

## 既知の制限

使用前に必ずご確認ください。

- **向きの検出には物理的証拠が必要です。** 180° の判定は綴じ穴に依存します。綴じ穴のないページ（文庫綴じ、ばら単葉、2 穴綴じ文書）は**自動回転されません**。これは意図的な設計です。既に正しい向きの表ページを回転してしまうのは、誰かが気づける도록残すより悪いとの判断です。当該ページは手動で回転させるか、綴じ穴なしページが本当に必要な場合は OCR にフォールバックする徹底モードを使用してください。
- **フラットベッドスキャナ出力向けに設計されています。** スマートフォン撮影の遠近変形には対応していません。
- **向きの閾値は約 300 DPI を前提に較正されています。** 600 DPI では綴じ穴の証拠が較正範囲外となり、「回転しない」にフォールバックします。
- **AI ランタイムは ONNX Runtime 1.14.1 に固定**されています（Win7 で動く最後のバージョン）。モデルを交換する前に `python tools\onnx_ops.py --diff ai\migan.onnx candidate.onnx` で演算子の互換性を確認してください。（LaMa は FFT 演算子の挙動に問題があるため、このバージョンの CPU カーネルでは採用されませんでした。）
- **アーカイブは Desktop、C ドライブのルート、システムフォルダ、ユーザープロファイルディレクトリの一括処理を拒否します。**
- **コード署名証明書が未発行**のため、初回起動時に Windows が発行元の警告を表示します。

## ソースからのビルド

**必要条件：** Windows と .NET Framework 4.x。それ以外はいりません。Visual Studio も NuGet の復元も不要です。

```bat
build.bat
```

出力は `dist\Restoria.exe` です。ビルドスクリプトは以下を行います。

1. `vendor\onnxruntime_c_api.h` を検出します。存在すれば AI 相互運用レイヤーを生成し（`src\Ai\OrtApi.Generated.cs`）、AI 付きでビルドします。存在しなければ AI なしでビルドし、他の機能には影響しません。
2. アイコン（`assets\app.ico`。`tools\IconGen.cs` が GDI+ のパス幾何で描画し、ソースがデザイン情報の唯一の源）とマニフェスト（`assets\app.manifest`。Win7〜11 の対応と `asInvoker` を宣言し、権限昇格を求めません）を埋め込みます。
3. .NET 4.x ランタイムを宣言する `.config` を生成します。
4. exe 隣接に PDB を出力し、製品名に合わせて改名します。これにより現場で取られたクラッシュレポートを一致するシンボルで解決できます。

> **製品名について：** `build.bat` は内部名 `dist\PicTool.exe` としてコンパイルし、その後 `appname.txt` の内容に従って公開名 `dist\Restoria.exe` にコピーします。両ファイルはバイト単位で同一です。`PicTool` は内部識別子とアセンブリ名前空間であり、ユーザーに見える名称は一貫して Restoria です。

### AI 機能の有効化

`ai\` フォルダを exe の隣にコピーします。

```bat
xcopy /e /y ai dist\ai
```

`onnxruntime.dll`、`migan.onnx`、`ocr\` の各モデル、`win7\` のシムが含まれます。合計 30 ファイル、約 59 MB です。不要なら `ai\` を削除してからビルドしてください。

### チェックの実行

```bat
build.bat                                  :: ビルド
dist\Restoria.exe --selftest               :: ① アルゴリズム自己テスト（終了コード 0）
dist\Restoria.exe --layout                 :: ② レイアウトスナップショット（ベースラインと比較）
python tools\check_resources.py --strict     :: ③ リソースゲート（LockBits ペアリング）
python tools\gate.py                      :: ④ 全ゲート（性能スモークテストを含む）
```

レイアウトベースラインは `tools\golden-layout.txt` にあります。UI を意図的に変更した場合は `--regen-layout` で再生成してください。

AI 生成物と性能スモークテストの各ゲートは固定テストページ `_probe\doc_test.png` を必要としますが、これは `Restoria.exe --make-fixture` で決定論的に生成されます。リポジトリに同梱されているため、新規クローンでも存在します。万一欠落しても、ゲートは現場で再生成し、再生成自体が失敗した場合のみ不合格とします。

性能ベースラインはマシンのタグを記録します。異なるマシンからのベースラインは暗黙の比較ではなく明示的に報告されます。ローカルで `--regen-perf` を実行して再構築してください。

## コマンドライン診断

スクリプト処理と不具合報告のためのヘッドレスモードです。レポートは `%TEMP%\PicTool-*.txt` に出力され、終了コードはクリーンで、ダイアログは表示されません。

| フラグ | 用途 |
|---|---|
| `--selftest` | アルゴリズムとインタラクションの自己テスト 134 件。終了コード 0 で全件パス |
| `--layout` | レイアウトスナップショット（リファクタリング前後で行単位で同一であるべき） |
| `--archive <入力> <出力> [dpi] [オプション]` | パイプラインをヘッドレス実行 |
| `--skew-test <ファイルまたはフォルダ> [n]` | 黒枠コントロール比較付きの傾き検出 |
| `--ai-check` / `--ai-check-silent` | AI ランタイムとモデルの検査（silent はインストーラの無人実行用） |
| `--ai-fill <入力> <出力> [x y w h]` | 1 領域を AI 補完してディスクに保存（オフライン比較用） |
| `--paper-fill <入力> <出力> [x y w h]` | 紙面再構築をディスクに保存 |
| `--make-fixture [パス]` | ゲートで使用する決定論的テストページを出力 |
| `--bench [golden] [--regen]` | 演算子ごとの計測と出力フィンガープリント |
| `--wheeltest[=フォルダ]` | キャンバス、左レール、右レール間のホイール経路 |
| `--uityping` | 入力フォーカスの判定検査（新旧の判定を並置） |
| `--undotest` | アンドウの予算とフレーム単位のロールバック検査 |
| `--cursortest` | カスタムカーソル形状の検査。スクリーンショットを保存 |
| `--droptest` | ドラッグ＆ドロップの受信ツリー検査 |

環境変数スイッチ：`PICTOOL_AI_TRACE=1`、`PICTOOL_OCR_TRACE=1`、`PICTOOL_SKEW_NOGUARD=1`、および `PICTOOL_RECOVERY_ROOT`（リカバリ領域をリダイレクトし、プローブがユーザーの実データに一切触れないようにします）。

## 構成

```
├── src/                  すべてのソース（68 個の .cs、約 26,000 行）
│   ├── Program.cs        エントリポイント、グローバル例外捕捉、診断ディスパッチ
│   ├── Core/             自己テストスイート、ベンチマーク、バージョン、リカバリ、ビットマップブリッジ
│   ├── Platform/         システムプローブ、WIA スキャン、ファイルユーティリティ
│   ├── Imaging/          純粋な画像アルゴリズム（UI 非依存）：洗浄、增强、補修、アーカイブ
│   ├── Ai/               オプショナル AI レイヤ：ONNX 相互運用、MI-GAN、OCR 向き判定
│   └── Ui/               画面とインタラクション（WinForms を参照するのはここだけ）
├── assets/               アイコンとマニフェスト。アイコンは tools\IconGen.cs が
│                         GDI+ のパス幾何で描画し、ソースがデザイン情報の唯一の源
├── _probe/               ゲート用の固定テストページ（--make-fixture で再生成可能）
├── tools/                ビルドと検証のツールチェーン
│   ├── gate.py           4 つのゲート：自己テスト + レイアウト + AI 生成物 + 性能
│   ├── check_resources.py リソースゲート（LockBits ペアリング）
│   ├── onnx_ops.py       ONNX 演算子互換性スキャン（モデル交換前に実行）
│   ├── archive_demo.py   アーカイブ前後の比較画像生成
│   ├── make_package.ps1  パッケージングチェーン（ビルド→組立→署名→自己検証）
│   └── install/          インストーラとアンインストーラのソース
├── ai/                   オプショナル AI ペイロード：ONNX ランタイム + MI-GAN + OCR モデル + Win7 シム
├── vendor/               onnxruntime_c_api.h（相互運用レイヤー生成用）
├── docs/                 多言語 README とアーキテクチャ解説
├── build.bat             ワンコマンドビルド
├── CHANGELOG.md          バージョン履歴
└── THIRD_PARTY_NOTICES   同梱のすべての第三者コンポーネントのライセンス
```

依存関係は一方向のみです。逆参照は禁止されます。

```
Ui ──→ Imaging / Ai / Platform / Core
Ai ──→ Platform（SysInfo）
Imaging ──→ Platform（少数）
Platform ──→ （なし）
```

`Imaging` と `Ai` には `System.Windows.Forms` を記述できません。アルゴリズムは引数を受け取り、新しいビットマップを返します。グローバル状態を変更しません。
