# Restoria

**Превращает планшетные сканы сшитого архива в чистые ровные страницы A4 — офлайн, на Windows 7–11.**

Ориентация определяется по отверстиям переплёта, удаляются пыль и неровный свет, красные печати остаются красными, а оригиналы не меняются ни на байт. Один исполняемый файл, без установщика, без сети.

**Для чего:** сшитые или пробитые документы, отсканированные на планшете при ~300 DPI.
**Не для чего:** фото с телефона (перспектива), клеевое скрепление (нет отверстий), сканеры с компенсацией изгиба.

![Шесть страниц, один клик, папка A4](images/demo.gif)

- **Требования:** Windows 7 SP1 → Windows 11 (.NET Framework 4.8, AnyCPU)
- **Интерфейс:** полностью собственная отрисовка на GDI+ с двойной буферизацией, поэтому не тормозит на старом оборудовании; светлая и тёмная темы
- **Код:** около 26 000 строк на C#, без сторонних пакетов NuGet, собирается компилятором, входящим в состав Windows

## Возможности

### Конвейер в один клик

Ориентация → обнаружение зеркала → удаление шума → коррекция наклона → уровни и автоматический тон → вывод A4.

- **Обычный** — баланс скорости и чистоты. Ориентация опирается только на физические признаки: отверстия переплёта.
- **Тщательный** — удаляет лишь самые очевидные пылинки и откатывает собственные действия, если начинает задевать символы. **Лучше оставить точку, чем потерять один штрих рукописного знака.** Для страниц без отверстий переплёта применяется определение ориентации по OCR. Подходит для бледного рукописного текста и документов, где важнее содержание, чем скорость.

При архивировании **создаются только новые файлы**; исходное изображение не изменяется ни на байт. Прерванный запуск продолжается с места остановки. Каждый пакет формирует отчёт: изменение размеров страниц, угол поворота и его обоснование, количество правок и затраченное время.

### Работа с отдельной страницей

| Вкладка | Назначение |
|---|---|
| Удаление | Кисть или выделение прямоугольником; пять режимов заливки: обычный, усиленный, смешанный, реконструкция бумаги, AI |
| Обрезка | Ручная обрезка или привязка к формату A4 |
| Ориентация | Ручной поворот или коррекция наклона в один клик (проекционный метод, ±20°) |
| Коррекция | Яркость, контраст, насыщенность, температура, уровни, гамма, резкость (каждое значение вводится кликом) |
| Печать | Восстановление выцветших красных печатей |
| Пакет | Применение фиксированных параметров ко всей папке |
| Сканирование | Прямая работа со сканером через WIA; выбор формата вывода (JPG/PNG/TIF) |
| Файлы | Массовое переименование, управление папками |
| Текст | Нанесение пометок на страницу |

### Необязательное AI-восстановление (MI-GAN)

- Модель MI-GAN на базе ONNX Runtime 1.14.1; продолжает длинные прямые структуры вроде линеек таблиц через повреждённый участок
- **Загружается в дочернем процессе, никогда в основном.** Если среда выполнения не загрузилась, AI-функции отключаются, всё остальное работает как прежде
- Поддержка Win7 через подмену таблицы импорта (подробности в комментариях `src/Ai/AiFill.cs`)

Весь пакет `ai/` — 30 файлов, около 59 МБ — нужен только для AI-восстановления и распознавания печатей.

### Инженерные гарантии

- **134 безоконных самопроверки** (`--selftest`): пороги алгоритмов, бюджет отмены, расположение восстановления, конфликты горячих клавиш
- **Регрессия по базовому снимку интерфейса** (`--layout-check`): объективное доказательство, что рефакторинг UI ничего не изменил
- **Четыре барьера** (`tools/gate.py`): самопроверки, базовый снимок, AI-артефакт, дымовой тест производительности
- **Непрерывная интеграция**: GitHub Actions собирает и прогоняет барьеры при каждом push
- Параллельная регрессия архива: тщательный режим при parallel=1/2/4 даёт побайтово одинаковый результат

## Известные ограничения

Прочитайте это, прежде чем рассчитывать, что инструмент справится с вашими материалами.

- **Для определения ориентации нужен физический признак.** Решение о повороте на 180° опирается на отверстия переплёта. Страница без отверстий — брошюра на клее, отдельный лист, документ с двумя отверстиями — **не будет повёрнута автоматически**. Это осознанный выбор: повернуть и без того ровную таблицу хуже, чем оставить перевёрнутую страницу заметной человеку. Для таких страниц используйте ручной поворот либо тщательный режим (он переходит на OCR).
- **Рассчитано на вывод с плоского сканера.** Снимки со смартфона имеют перспективные искажения и не обрабатываются.
- **Пороги ориентации рассчитаны примерно на 300 DPI.** При 600 DPI признак отверстий выходит за калиброванное окно, и инструмент переходит в режим «без поворота».
- **Среда выполнения AI зафиксирована на ONNX Runtime 1.14.1** — последней версии, загружающейся на Windows 7. Перед заменой модели проверьте совместимость операторов командой `python tools\onnx_ops.py --diff ai\migan.onnx candidate.onnx`. (LaMa отклонён из-за некорректной работы FFT-оператора в CPU-ядрах этой версии.)
- **Архивирование отказывается работать над** рабочим столом, корнем диска C:, системными папками и домашним каталогом пользователя.
- **Сертификат подписи кода ещё не получен,** поэтому при первом запуске Windows покажет предупреждение о неизвестном издателе.

## Сборка из исходного кода

**Требования:** Windows и .NET Framework 4.x. Больше ничего не нужно — ни Visual Studio, ни восстановления пакетов NuGet.

```bat
build.bat
```

Результат — `dist\Restoria.exe`. Скрипт сборки:

1. Проверяет наличие `vendor\onnxruntime_c_api.h`. Если файл есть, генерируется слой взаимодействия с ONNX (`src\Ai\OrtApi.Generated.cs`) и сборка идёт с поддержкой AI; если нет — собирается версия без AI, всё остальное работает как прежде.
2. Встраивает значок (`assets\app.ico`, нарисованный как геометрия контуров GDI+ в `tools\IconGen.cs` — исходный код служит единственным источником дизайна) и манифест (`assets\app.manifest`, объявляющий поддержку Win7–11 и `asInvoker`, чтобы программа никогда не запрашивала повышения прав).
3. Создаёт `.config` с объявлением среды выполнения .NET 4.x.
4. Создаёт PDB рядом с исполняемым файлом и переименовывает его вместе с продуктом, чтобы отчёт о сбое с рабочей машины можно было сопоставить с подходящими символами.

> **О названии продукта:** `build.bat` собирает файл под внутренним именем `dist\PicTool.exe`, затем копирует его под опубликованным именем `dist\Restoria.exe` (из `appname.txt`). Оба файла побайтово идентичны. `PicTool` — внутренний идентификатор и пространство имён сборки; во всех местах, которые видит пользователь, название — Restoria.

### Включение функций AI

Скопируйте папку `ai\` рядом с исполняемым файлом:

```bat
xcopy /e /y ai dist\ai
```

В ней находятся `onnxruntime.dll`, `migan.onnx`, модели в `ocr\` и прокладки в `win7\` — всего 30 файлов, около 59 МБ. Если они не нужны, удалите `ai\` перед сборкой.

### Запуск проверок

```bat
build.bat                                  :: сборка
dist\Restoria.exe --selftest               :: 1. самопроверка алгоритмов (код 0 = успех)
dist\Restoria.exe --layout-check                 :: 2. снимок интерфейса (сравнение с базой)
python tools\check_resources.py --strict     :: 3. барьер ресурсов (парность LockBits)
python tools\gate.py                      :: 4. все барьеры, включая дымовой тест производительности
```

База снимка интерфейса лежит в `tools\golden-layout.txt`. После намеренного изменения UI пересоздайте её ключом `--regen-layout`.

Барьеры AI-артефакта и производительности требуют фиксированной тестовой страницы `_probe\doc_test.png`, которую детерминированно создаёт `Restoria.exe --make-fixture`. Она хранится в репозитории, поэтому свежая копия её содержит; если файл пропадёт, барьер создаст его заново и провалится только если не сработает и генерация.

Базовая линия производительности хранит метку машины. База с другой машины не сравнивается молча, а сообщается явно — пересоберите её локально ключом `--regen-perf`.

## Диагностика из командной строки

Безоконные режимы для скриптов и разбора ошибок. Отчёты попадают в `%TEMP%\PicTool-*.txt`, коды возврата чистые, диалоговых окон нет.

| Ключ | Назначение |
|---|---|
| `--selftest` | 134 самопроверки алгоритмов и взаимодействия; код 0 = все пройдены |
| `--layout-check` | Снимок интерфейса (после рефакторинга должен совпадать построчно) |
| `--archive <вход> <выход> [dpi] [опции]` | Прогон конвейера без окна |
| `--skew-test <файл или папка> [n]` | Проверка определения наклона с контрольным сравнением по чёрной рамке |
| `--ai-check` / `--ai-check-silent` | Проверка среды выполнения и моделей AI (silent — для автоматической установки) |
| `--ai-fill <вход> <выход> [x y w h]` | AI-восстановление области с сохранением на диск |
| `--paper-fill <вход> <выход> [x y w h]` | Реконструкция участка бумаги с сохранением на диск |
| `--make-fixture [путь]` | Экспорт детерминированной тестовой страницы для барьеров |
| `--bench [golden] [--regen]` | Замеры по операторам и отпечатки результатов |
| `--wheeltest[=папка]` | Маршрутизация колеса мыши: холст, левая и правая панели |
| `--uityping` | Проверка правила фокуса ввода, старый и новый предикаты рядом |
| `--undotest` | Проверка бюджета отмены и покадрового отката |
| `--cursortest` | Проверка формы собственного курсора, оставляет снимок экрана |
| `--droptest` | Проверка дерева приёма перетаскивания |

Переключатели окружения: `PICTOOL_AI_TRACE=1`, `PICTOOL_OCR_TRACE=1`, `PICTOOL_SKEW_NOGUARD=1`, а также `PICTOOL_RECOVERY_ROOT` (перенаправляет область восстановления; используется проверками, чтобы они никогда не касались реальных данных пользователя).

## Структура

```
├── src/                  Все исходники (68 файлов .cs, около 26 000 строк)
│   ├── Program.cs        Точка входа, перехват исключений, разбор диагностических режимов
│   ├── Core/             Набор самопроверок, эталон производительности, версия, восстановление, мост к Bitmap
│   ├── Platform/         Определение системы, сканирование WIA, файловые утилиты
│   ├── Imaging/          Чистые алгоритмы изображений (без зависимости от UI): очистка, усиление, ремонт, архивирование
│   ├── Ai/               Необязательный слой AI: взаимодействие с ONNX, MI-GAN, OCR-судья ориентации
│   └── Ui/               Интерфейс и взаимодействие (единственное место со ссылкой на WinForms)
├── assets/               Значки и манифесты. Значок рисуется как геометрия контуров GDI+
│                         в tools\IconGen.cs — исходный код служит единственным источником дизайна
├── _probe/               Фиксированная тестовая страница для барьеров (пересоздаётся через --make-fixture)
├── tools/                Сборочный и проверочный инструментарий
│   ├── gate.py           Четыре барьера: самопроверки + интерфейс + AI-артефакт + производительность
│   ├── check_resources.py Барьер ресурсов (парность LockBits)
│   ├── onnx_ops.py       Сканирование совместимости операторов ONNX (запускать перед заменой модели)
│   ├── archive_demo.py   Генератор сравнительных изображений до/после
│   ├── make_package.ps1  Цепочка упаковки (сборка → компоновка → подпись → самопроверка)
│   └── install/          Исходники установщика и деинсталлятора
├── ai/                   Необязательный пакет AI: среда ONNX + MI-GAN + модели OCR + прокладки Win7
├── vendor/               onnxruntime_c_api.h (генерация слоя взаимодействия)
├── docs/                 Переводы и заметки по архитектуре
├── build.bat             Сборка одной командой
├── CHANGELOG.md          История версий
└── THIRD_PARTY_NOTICES   Лицензии всех сторонних компонентов, входящих в поставку
```

Зависимости идут в одну сторону; обратные ссылки запрещены:

```
Ui ──→ Imaging / Ai / Platform / Core
Ai ──→ Platform (SysInfo)
Imaging ──→ Platform (немного)
Platform ──→ (ничего)
```

В `Imaging` и `Ai` запрещено упоминание `System.Windows.Forms`; алгоритмы принимают параметры и возвращают новые растровые изображения, не изменяя глобальное состояние.
